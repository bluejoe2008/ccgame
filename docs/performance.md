# 寻路与渲染优化对比

测量日期：2026-11-25。基线为 `caaf64f`，每组运行 3 次，耗时取中位数。

## 团队行军

相同种子 `2296959562`、相同坦克数量和起点、相同目的地；在相同的开阔地形上推进 12 秒游戏时间。计时不包含世界初始化和地形预热；包含行进、避障、碰撞与正常模拟。没有敌军。

| 坦克数 | A* 次数（优化前 → 后） | 模拟计算耗时（前 → 后） | 耗时减少 |
| --- | --- | --- | --- |
| 18 | 10 → 3 | 325.05 → 246.64 ms | 24.1% |
| 54 | 47 → 6 | 1485.67 → 774.68 ms | 47.9% |
| 108 | 136 → 40 | 3947.76 → 1329.39 ms | 66.3% |

上表是整套优化的收益，包括附近单位索引、局部避障、连通性检查和团队跟随。优化前也有每组最多 6 人的共享路径，本次提高到最多 18 人，以多列跟随避免过长队列。跟随者不独立执行 A*；领队失效时选举替代者并计算新路径。

为了区分团队改动与其他优化，另保留旧团队逻辑，仅应用其余核心优化，再与新团队逻辑比较：

| 坦克数 | 旧团队逻辑 | 新团队逻辑 | 团队改动额外减少耗时 |
| --- | --- | --- | --- |
| 18 | 288.16 ms | 246.64 ms | 14.4% |
| 54 | 863.61 ms | 774.68 ms | 10.3% |
| 108 | 1475.82 ms | 1329.39 ms | 9.9% |

各组结束时所有坦克存活，未发现碰撞半径内的单位重叠。优化后平均行进距离均增加，因此收益不是通过停止部队运动得到的。计数与耗时会随地图、拥堵、交战状态和机器性能变化。

复现：

```bash
node benchmarks/navigation.cjs caaf64f
```

输出包含每轮原始记录、中位数、初始领队/跟随者数量、寻路次数、平均行进距离和重叠检查。`before` 是旧实现，`core` 保留旧团队逻辑并启用其他核心优化，`after` 是完整新实现。

## 当前战局副本

另对第 77 局的一份固定存档测量 100 个模拟步（4 秒游戏时间）：最初约 8.70 秒，加入附近单位索引、局部避障桶和距离预筛后约 3.16 秒；进一步增加区域连通性缓存后约 2.65 秒。该测量包含 CPU 采样器开销，不与上述开阔地行军测试混用。

上线前旧服务出现战局线程超时并返回 503，正常退出未能完成最终保存，因此从最近的服务器存档恢复了同一第 77 局。地图种子及对局 ID 均保留。

恢复后的 10.92 秒采样中，游戏每现实秒推进约 1.002 游戏秒；战局线程占用约 62.9% 单核 CPU。轻量状态请求平均 26.83 ms，战况快照平均 107.20 ms，采样结束时有 215 个活动单位和 37 座建筑。数据仅代表这段采样，不保证所有规模和地图都保持实时速度。

## 浏览器

默认画面比例按用户要求变为之前的 50%。比较双方均使用新比例 0.35、1500×1000 窗口、服务器侧无头 Chromium。宽视野地块超过旧预览缓存容量时，会不断重新合成地形。将地形单独放在可见画布，并增大地块/预览缓存后，密集区域的地面绘制平均耗时约从 77 ms 降到 2 ms；滚图约从 181 ms 降到 16 ms。

该观察使用同一初始存档的独立运行副本，但单位会继续生产和移动，前后数量有所变化。它说明热点改善，不是严格的固定帧率对照，也不代表玩家电脑的实际帧率。

## 验证范围

自动检查覆盖索引与全量碰撞检测的一致性、单位移动及上下运输机后的索引更新、断路与桥梁连通性、本地绕障安全、跟随者不执行 A*、领队失效后的替换，以及原有多人权限和存档规则。浏览器检查覆盖半比例视野、T 同类选择、选取与框选、弹出菜单和输入框中的快捷键隔离。
